# にじいろ ドリームトレイン

このリポジトリの子供向け15作品を、列車の冒険としてつなぐ新作です。**元のゲームを同一オリジンのiframeで実行**するため、各作品の絵・音・操作・物理演算・ルール・全ステージ・育成・セーブは本物を使います。似た見た目の簡易ミニゲームに置き換えていません。大人向けの情報ダッシュボード「AI Builders Radar」は対象外です。

## 遊びの流れ

1. 3駅・5駅・全15駅のきっぷを選ぶ、または好きな駅を選ぶ。
2. 駅の案内を見て元ゲームの世界へ入る。元ゲームのタイトルから遊ぶ。
3. 今回の正解・発見・工作・クリアなど、駅固有の「おねがい」を達成するとスタンプと飾りが届く。既存のセーブやタイトルの待機時間は達成として扱わない。
4. 達成しても中断せず、そのまま遊び続けられる。「つぎの えきへ」で次のゲームへ。未達成でも「つぎへ」で移動でき、罰や制限はない。
5. 集めた15種類の飾りを5両のワゴンへ自由に載せ、列車の色も選ぶ。全15駅で小目標を達成するとお祭りの演出が開く。

旅程は遊びの種類が連続しにくく、未取得の駅から優先して候補を選びます。3駅の短い旅では、導入の長いRPG・探偵の長編・こっそりトレジャーを候補から外します（個別選択や5駅／15駅では遊べます）。長いRPGや自由制作のゲームもあるため、所要時間の上限や自動切替は設けません。スタンプは**旅の小目標の達成**であり、元ゲーム全体のクリアを意味しません。到着の案内は任意の日本語読み上げに対応。各ゲーム内の音声設定は元ゲームの設定を使います。

## 構成と保存

- `catalog.js`: 対象15作品、駅の案内、固有目標と飾り。
- `engine.js`: 旅程の生成、スタンプ、保存データの検証。
- `app.js`: 旅の画面、元ゲームの起動／終了、切替、パスポート、飾りつけ、お祭り。
- `bridge.js`: 起動した元ゲームの中でのみ読み込む連携。既存の公開APIやイベントを観測する。関数を包む場合は元の`this`・引数・戻り値を保持し、処理成功後に通知する。元のソースやゲームルールを書き換えない。
- `style.css`: PC／タブレット／スマートフォンのレイアウト。タップ領域、キーボードのフォーカス、`prefers-reduced-motion`に対応。
- 列車の絵はオリジナルSVG。仲間と飾りの絵は`../nijiiro-treasure/art.js`、各作品の写真は既存の`../thumbs/`から参照。

列車の記録は`localStorage['dream-train.v1']`、列車の案内音声は`dream-train.v1.voice`。旅程と途中の目標数、取得スタンプ、飾り、色を保存します。各ゲーム本来のlocalStorage／IndexedDBのキーはそのまま共用するので、元ページで遊んだ続きも選べます。

寄り道のきっぷを見るだけでは現在の旅程を消しません。実際に寄り道を開始すると元の旅程を一時保管し、寄り道を終えると元の旅程へ戻します。ゲームの状態自体は各作品の保存粒度に従います（すべてのアニメーションや画面位置を復元するものではありません）。

iframeは常に1つ。離れる前に元ゲームの保存・`pagehide`処理を走らせ、必要な非同期保存を待ち、前のiframeを破棄します。裏で15本の描画ループや音を鳴らし続けません。受信する通知は同一オリジン・現在のiframe・ゲームID・訪問ごとのトークンを照合します。観測は200msごと。リッキーの伸縮は描画フレームでも観測します。終了直前にも読み取り、最後の操作を取りこぼさないようにしています。

保存が使えない場合もその場では遊べますが、ページを閉じた後の復元はできません。元ゲームで必要なWebGLなどのブラウザ機能は引き続き必要です。元ゲームが使う外部フォントは各作品の既存参照です。ゲーム本体を重複コピーしないため、単体フォルダを切り離さずリポジトリ全体で配信してください。

## 起動と検証

ビルド不要。元のES Modulesのゲームも動かすためHTTP配信で起動します。

```sh
# リポジトリのルート
python3 -m http.server 8770
# http://localhost:8770/dream-train/

node dream-train/tests/engine.cjs
node dream-train/tests/browser.cjs
```

ブラウザテストにはPlaywrightとChromiumを使います。`DREAM_TEST_URL`／`CHROMIUM_PATH`で変更できます。

- 15作品それぞれの起動、連携の準備、タイトルで誤ってスタンプを与えないこと。
- 3駅の旅：元クイズの回答ボタン→元工作の配置処理→元リッキーの顔を実際にドラッグ→旅の終了→飾りつけ→保存復元。
- 残りのアダプターは元エンジンの公開アクション／結果APIを使って統合を検証。元の全長編や全ステージを最初から最後まで自動プレイするテストではありません。
- 別ウィンドウからの不正通知拒否、二重スタンプ防止、未達成のスキップ、旅程と寄り道復帰、全駅達成のお祭り、5画面サイズ、保存不能時の動作。

元ゲームの変更時には、上表の公開API・保存形・DOMとの互換性を確認してください。
