### 4.2 データモデル（仕様18.3 に合わせる）

```ts

  element: 'light', role: 'support' | 'attacker' | 'caster' | 'tank' | 'status' | 'speed' | 'special',
  growthType: 'early' | 'late' | 'balanced' | 'offense' | 'endure' | 'variable',
  baseStats: { hp, mp, atk, def, mag, spr, spd }, growthRates: {...}, levelCap, 
  resistances: { fire: -1..4 /* 4=吸収 */, ... , sleep, paralysis, confusion, poison },
  skills: [{ level, skillId }], breedingGroup: 'slime-light' など, habitatIds: ['d01_2:1-2', ...],
  spriteId: 'mon_001_luna_slime', description, lore?, variantOf?: 'm00x' /* 亜種の元 */ }

// MonsterInstance（セーブ）… v1 の MonsterInstance に追加
{ ...v1, speciesId: 'm001', history: HistoryEntry[] /* 加入・初ボス参加・Lv節目・配合誕生 */,
  labels: ('fav' | 'training' | 'breedCandidate')[], equipment?: equipId, breedingCount, acquiredAt }

// DungeonDefinition
{ id: 'd01_3', chapter: 1, name: 'ささやきの森', theme: 'forest',
  floors: [{ type: 'forest' | 'maze' | 'hall' | 'water' | 'treasure' | 'highland' | 'windmill' | 'shrine' | 'corridor' | 'floating',

  midBoss?, bossId?, clearConditions, rewards }

// BreedingRecipe / StoryEvent は仕様の項目に合わせる（requiredItems / unlockConditions / triggerConditions / eventActions）
```

- ID は `m001`〜`m200`（数値番号と一致）。スプライトは `mon_###_slug`。
- **モンスターを追加しても戦闘ロジックを書き換えない**：特殊な能力（反射・吸収・属性切替・変則成長）は「特性フラグ＋スキル」で表現し、戦闘エンジンは汎用処理だけを持つ。

### 4.3 戦闘の拡張（バランスを壊さない作り方）

1. **7能力**：`wisdom` を `mag`（魔力）と `spr`（精神）に分割。呪文ダメージ＝`威力 + 魔力×0.12 − 精神×k`（k は初期値0から、シミュレーションで決める）。回復量は精神を参照。
2. **8属性＋吸収**：耐性レベル −1/0/1/2/3 に **4＝吸収** を追加（倍率表 `elementMultiplier` に1行足すだけ）。吸収・無効を持つ種はデータ検証テストで数を制限。
3. **ボスの行動台本**（`src/data/bosses`）：`turnN`・`hpBelow` などの条件と `summon` / `reflect` / `buffSelf` / `changeElement` / `phase` などのアクションをデータで定義。エンジンは台本を順に評価するだけ。
4. **状態の追加**：反射（呪文を返す）・封印（スキル不可）・行動順操作。
5. v1 の戦闘テスト（`tests/unit/battle.test.ts`）はすべて通ったまま拡張する。

### 4.4 ダンジョンの作り方（Q14）

- 参考画像2の「ダンジョンマップ例」にある**階層タイプ**ごとに、手作りの部屋パーツ（例：広間・通路・水場の島・宝物庫・風車の丘・回廊・浮島）を用意し、`RoomGen` が接続して1フロアを作る。
- **固有イベント・ギミック・ボス部屋は固定**（ランダムで見逃さない）。宝箱・敵・小部屋の並びはシードで変化。
- ギミックはデータで定義：水流（流される床）、風の橋（時間で出る足場）、毒花（踏むと毒）、強風（押し流し）、凍結床（すべる）、溶岩（ダメージ床）、浮遊床、暗闇（視界が狭い。v1 の洞窟と同じ）など。
- 現行の固有イベント基盤（`events.ts`・`EventEngine`）はそのまま「EventPlacement」として使う。

### 4.5 ストーリーの作り方

- `StoryEvent`（条件 → 台詞 → アクション[フラグ・解放・入手・戦闘・マップ変化]）をデータで定義し、`StoryEngine` が評価する（v1 の `talkTo` の分岐を置き換える）。
- **ルナスライムの固有リアクション**：パーティにいる時だけ流れる台詞・演出をイベントごとに定義（震える・紋章に反応・記憶を感じ取る）。
- **NPC会話**：NPCごとに「章×条件」の会話表。
- **記録室**（アステラの原初の記録室）：見たストーリーイベントをいつでも読み返せる（v1 の「ぼうけんメモ」を発展）。

### 5.1 モンスター200体（参考画像1）

1. **抽出ツール `tools/sprites/extract_v2.py`**（v1 の `extract.py` の手法を流用）

| 難易度曲線（balance） | 章ごとの想定パーティで各ダンジョンの連戦勝率・中ボス・章ボスの勝率（v1 と同じ「おおむね範囲内」方式） |
| 進行（integration） | 第1章をタイトルからボス撃破まで自動で通す／章クリアで機能が解放される／保存→再開で進行が戻る |
| 移行（unit） | v1・v2・v3 のセーブを読み込み、引き継ぎ内容が正しい・バックアップが残る |
| e2e（Playwright） | タッチ操作で町→ダンジョン→戦闘→仲間化→配合→保存→再開。各画面を撮影して参考画像と並べて確認 |
| アセット | 200枚の存在・サイズ・placeholder 一覧・似すぎ一覧 |

---

## 9. ゲームバランスの方針（v1 を踏襲）

- `balance.ts` の係数・敵AI・仲間化・経験値の分け方・配合の+値の考え方は維持。新しい要素（精神・吸収・装備）は**既定値を「v1 と同じ結果」になる値**から始め、シミュレーションで調整する。
- 章ごとの想定レベル（Q15）：第1章 1〜10／第2章 8〜16／第3章 14〜22／第4章 20〜28／第5章 26〜34／第6章 32〜40／第7章 38〜46／第8章 44〜52／第9章 50〜56／第10章 54〜60／第11章 58〜64／第12章 62〜68／クリア後 68〜99。
- 目標勝率（想定パーティ・オート）：通常フロア連戦 60〜100%、中ボス 50〜90%、章ボス 30〜80%、隠しボス 10〜50%（v1 と同じ考え方）。

## 10. リスクと対策

| リスク | 対策 |
|---|---|
| 参考画像1の解像度が低く、抽出したドット絵が粗い／隣のマスや文字が混ざる | v1 で実績のある抽出手法＋マス単位の切り出し。失敗分は placeholder として明示し、手修正の候補リストを作る |
| 200種のバランスが崩れる | 役割×ランクのテンプレートで能力を生成し、個別補正は差分だけ。データ検証とシミュレーションで常時チェック |
| 物語・会話の量が膨大 | 章ごとに StoryEvent をデータで追加。Phase ごとに対象章だけを書く |
| 旧セーブとの互換 | 移行前バックアップ・移行テスト・引き継ぎ方式（Q9） |
| 端末負荷（画像200枚・大きいマップ） | アトラスの事前読込、タイル描画のキャッシュ（v1 方式）、画面外は描かない |
| 規模が大きく途中で破綻する | 仕様19章のとおり縦切りで進め、各フェーズの受け入れ基準を満たしてから次へ |
